# compute-scroll-into-view

## 4.0.0

### Major Changes

- [#938](https://github.com/scroll-into-view/compute-scroll-into-view/pull/938) [`d026dba`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/d026dba0bb8b13a675c91a00948f9d897648ff6f) Thanks [@tembo](https://github.com/apps/tembo)! - Ship ESM only, with the package `exports` generated by tsdown.

  - The CommonJS build (`dist/index.cjs`) is removed. On Node.js 20.19+ and 22.12+, `require('compute-scroll-into-view')` still works through `require(esm)` and returns `{ compute }`.
  - TypeScript projects with CommonJS files must use `"module": "nodenext"`. With `"module": "node16"`, TypeScript reports TS1479 when CommonJS files import an ES module. ESM files and `"moduleResolution": "bundler"` are unaffected.
  - `exports` is now `{ ".": "./dist/index.js" }`. The `source` export condition and the `source` and `typings` fields are removed. `types` replaces `typings`.

- [#953](https://github.com/scroll-into-view/compute-scroll-into-view/pull/953) [`88378bf`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/88378bfe3c7ba978778c9e29e1648ee0286324bc) Thanks [@stipsan](https://github.com/stipsan)! - `compute(target, options)` is spec-only. The `scrollMode`, `boundary` and `skipOverflowHiddenElements` options are removed, and are middleware instead, with the same behavior. The built-in middleware are exported from `compute-scroll-into-view/middleware`, so the main entry only has `compute` and its types. Middleware can also change how scroll containers are found and measured, like `scroll-margin` and `scroll-padding`. `options` is now optional.

  ```js
  import { compute } from 'compute-scroll-into-view'
  import {
    boundary,
    onlyIfNeeded,
    skipOverflowHiddenElements,
  } from 'compute-scroll-into-view/middleware'

  // Before: compute(node, { scrollMode: 'if-needed', boundary: list, skipOverflowHiddenElements: true })
  compute(node, {
    middleware: [boundary(list), skipOverflowHiddenElements(), onlyIfNeeded()],
  })
  ```

  - Put `onlyIfNeeded()` after the other middleware, which is how the options combined.
  - The `ScrollMode` type is removed. `ComputeOptions` is an alias of `Options`, and the `Middleware`, `MiddlewareState`, `MiddlewareReturn`, `Rects` and `SideObject` types are exported from `compute-scroll-into-view`.

### Minor Changes

- [#952](https://github.com/scroll-into-view/compute-scroll-into-view/pull/952) [`3a93d4c`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/3a93d4cbf6c6aa5a9324013d61324ce4e66588a2) Thanks [@stipsan](https://github.com/stipsan)! - Add the `container` option from the CSSOM View spec's `ScrollIntoViewOptions`. `container: 'nearest'` only scrolls the target's nearest scroll container, or the viewport if it has none. The default, `'all'`, scrolls every scroll container as before.

- [#966](https://github.com/scroll-into-view/compute-scroll-into-view/pull/966) [`245679d`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/245679d7e2e857fd907215ebb1d46bca5131ad2b) Thanks [@stipsan](https://github.com/stipsan)! - Scroll the scroll containers and the viewport of the parent document too, when the target is in a same-origin iframe, as `Element.scrollIntoView()` and the CSSOM View spec do. They align the `<iframe>` where the scrolling inside the frame left the target, up to the top-level document. Cross-origin parents aren't reachable, and aren't scrolled. A `position: fixed` target in a frame doesn't move with the frame's viewport, so only the parent document is scrolled for it. This also covers scrolling a frame's target from inside the frame ([#694](https://github.com/scroll-into-view/compute-scroll-into-view/issues/694)).

- [#951](https://github.com/scroll-into-view/compute-scroll-into-view/pull/951) [`520fd20`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/520fd2015f977163251773d821cde14a58d51c29) Thanks [@stipsan](https://github.com/stipsan)! - Respect `scroll-padding` and align `scroll-margin` like browsers do.

  - `scroll-padding` on scroll containers, and on the root element for the viewport, is now part of the alignment ([#831](https://github.com/scroll-into-view/compute-scroll-into-view/issues/831)). Padding in percentages is supported.
  - `scroll-margin` of the target now works with `block: 'center'` and `'nearest'`, and together with `scroll-padding` ([#933](https://github.com/scroll-into-view/compute-scroll-into-view/issues/933)).
  - `scrollMode: 'if-needed'` only counts a target as visible when its `scroll-margin` box is within the scroll containers' `scroll-padding` ([#817](https://github.com/scroll-into-view/compute-scroll-into-view/issues/817)). For example, a target behind a fixed header that is covered by `scroll-padding-top` is scrolled into view.
  - `nearest` is measured from the padding edge of scroll containers with borders, instead of the border edge.

- [#964](https://github.com/scroll-into-view/compute-scroll-into-view/pull/964) [`ed654a2`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/ed654a2c2173f4e7fe35541c763de372d04fa740) Thanks [@stipsan](https://github.com/stipsan)! - Land on the target's own snap position in its nearest scroll container when that's a scroll snap container, as the CSSOM View spec requires. On each axis that the container's `scroll-snap-type` snaps, the target's `scroll-snap-align` replaces `block` or `inline` there. The outer scroll containers now align the target from where the browser actually snaps the inner one.

- [#970](https://github.com/scroll-into-view/compute-scroll-into-view/pull/970) [`46be135`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/46be135a23ba7a2f530976612c853e171bca5776) Thanks [@stipsan](https://github.com/stipsan)! - Add the `selection()` middleware, which scrolls a text selection into view instead of the target element, like editors keep the caret in view ([#902](https://github.com/scroll-into-view/compute-scroll-into-view/issues/902)). It takes a `Selection` or a `Range`, and defaults to the document's selection. The focus end is aligned, where the caret is: a collapsed caret is measured as the character or node next to it, so empty lines work too. `align: 'bounds'` aligns the whole selection instead. `compute` still walks the target's ancestors, so pass an element inside the editor. `onlyIfNeeded()` checks the selection when it runs after `selection()`.

- [#950](https://github.com/scroll-into-view/compute-scroll-into-view/pull/950) [`28e19bc`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/28e19bc09e6433b29233df8ff484777611a94caf) Thanks [@stipsan](https://github.com/stipsan)! - Follow the target's `writing-mode` and `direction`, like browsers do, and support negative scroll offsets.

  - `block` and `inline` now refer to the target's block and inline axes. For example, `inline: 'start'` aligns to the right edge of a right-to-left target, and `block: 'start'` aligns to the right edge of a `vertical-rl` target. Horizontal left-to-right targets work as before.
  - Scroll containers that overflow to the left or top, like right-to-left or `vertical-rl` ones, now get the negative `left` and `top` offsets browsers use for them, instead of being clamped to 0 ([#821](https://github.com/scroll-into-view/compute-scroll-into-view/issues/821)).
  - Scrollbars on the left side of a scroll container are accounted for.

### Patch Changes

- [#960](https://github.com/scroll-into-view/compute-scroll-into-view/pull/960) [`a51675f`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/a51675feb6bfeb5fe2cdc98b7a88376a812b947e) Thanks [@stipsan](https://github.com/stipsan)! - Scroll the body when it's a scroll container. Its overflow only applies to the viewport when the root's overflow is `visible`, so a body with `overflow: auto` under a root with `overflow: hidden`, `auto` or `clip` is scrolled now, like `Element.scrollIntoView()` does.

- [#949](https://github.com/scroll-into-view/compute-scroll-into-view/pull/949) [`76f855d`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/76f855d38bd49a1c26b2fdded8deb21be9ccd87e) Thanks [@stipsan](https://github.com/stipsan)! - Declare the supported browsers as [Baseline 2019](https://web.dev/baseline) in the `browserslist` field of `package.json`, and build for it. The bundle now also compiles away optional catch binding for legacy Edge 18, and stays free of optional chaining and nullish coalescing. `dist/index.d.ts.map` is no longer published, as it pointed at `src/`, which isn't published either. `dist/index.js.map` still embeds the source.

- [#957](https://github.com/scroll-into-view/compute-scroll-into-view/pull/957) [`e724874`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/e724874959adfb704f1e57849020b52aab92628e) Thanks [@feritcemkahraman](https://github.com/feritcemkahraman)! - Don't scroll `overflow: visible` elements inside an iframe. Only the iframe document's viewport (its root or scrolling element) is clipped by the iframe and scrolled when its content overflows it.

- [#936](https://github.com/scroll-into-view/compute-scroll-into-view/pull/936) [`aaaccf9`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/aaaccf9282af9e9a5cef4da1919f533548af4bca) Thanks [@tembo](https://github.com/apps/tembo)! - Check for `HTMLElement` and `ShadowRoot` properties with type guards instead of type assertions. The checks are the same, so behavior is unchanged. The type declarations now use the JSDoc `@default` tag instead of TSDoc's `@defaultValue`.

- [#958](https://github.com/scroll-into-view/compute-scroll-into-view/pull/958) [`3b64201`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/3b64201cf0ed8406afc3f03abca7c196764eaaab) Thanks [@satouriko](https://github.com/satouriko)! - Only scroll the scroll containers in the containing block chain of the target, like `Element.scrollIntoView()` does. Scroll containers that an absolutely or fixed positioned target escapes don't move it, so they aren't scrolled anymore, and the viewport isn't scrolled for a fixed positioned target either. Containing blocks follow `position` and the properties that contain positioned descendants, like `transform`, `filter` and `contain`. Middleware still visit those scroll containers, with `scrollable: false`.

- [#961](https://github.com/scroll-into-view/compute-scroll-into-view/pull/961) [`4796634`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/479663461c0ad6867d9c0864033ee2e3932ac56f) Thanks [@stipsan](https://github.com/stipsan)! - Scroll the viewport when the target is the scrolling element, or the root element in quirks mode. They have no ancestor that scrolls the viewport, so `compute(document.body)` returned no actions in quirks mode, and `compute(document.documentElement)` didn't in standards mode.

- [#956](https://github.com/scroll-into-view/compute-scroll-into-view/pull/956) [`9a21f0c`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/9a21f0c3a71e557c7363f55e2ff4830c242ef8fb) Thanks [@Remiscan](https://github.com/Remiscan)! - Scroll the scroll containers in a shadow tree that a slotted target is laid out in. The parent walk now goes from an element to its `assignedSlot`, before its parent element, so the slot's ancestors in the shadow tree are scrolled too, like `Element.scrollIntoView()` does.

- [#971](https://github.com/scroll-into-view/compute-scroll-into-view/pull/971) [`f1fc35b`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/f1fc35bc791ceefa53e57f8b81306c3c7d675b8a) Thanks [@stipsan](https://github.com/stipsan)! - Shrink the published bundle by about a fifth when minified. Measuring the four sides of a box and scrolling each axis now share one code path, and `getPropertyValue()` replaces the per-side style lookups. Behavior is unchanged.

- [#962](https://github.com/scroll-into-view/compute-scroll-into-view/pull/962) [`e49fb1b`](https://github.com/scroll-into-view/compute-scroll-into-view/commit/e49fb1bdd1569a6a3e35ff201b35e9950c034ec1) Thanks [@stipsan](https://github.com/stipsan)! - Use the target's own document and window for viewport measurements, so scrolling a target inside a frame works when `compute` is called from the parent document.
